FIND-ME 프론트엔드 연동 안내 (로그인 · 프로필 · 카드 피드)
갱신일: 2026-11-09


[1] 역할 나누기
------------------------------------------------------------
- 회원가입·로그인: 프론트가 Supabase Auth로 처리
- 프로필·성향 조회: 프론트가 로그인 토큰을 붙여 백엔드 API 호출
- DB 테이블은 프론트에서 직접 접근할 수 없음.
  supabase.from(...) 대신 백엔드 API를 호출할 것


[2] 현재 사용 가능한 API
------------------------------------------------------------
GET   /health   서버 상태 확인 (토큰 불필요)
POST  /me       프로필 최초 등록
GET   /me       내 프로필과 성향 조회
PATCH /me       프로필 수정
GET   /feed     다음에 보여 줄 카드 목록
POST  /reactions  카드 반응 저장 + 성향 갱신

아직 없는 API: /me/report, /push/subscribe

- 로컬 주소: http://localhost:8000
- 요청 형식 확인: http://localhost:8000/docs
- 서버 배포 전이라 지금은 로컬에서만 호출 가능
- CORS 기본 허용 주소: http://localhost:5173
  다른 주소를 쓰면 백엔드에 알려 줄 것

[4] 구현할 화면과 흐름
------------------------------------------------------------
1. 회원가입·로그인 화면
   - supabase.auth.signUp(), supabase.auth.signInWithPassword() 사용
   - Supabase에서 이메일 인증이 켜져 있으면 인증 전까지 세션이 생기지 않음

2. 로그인 직후 GET /me 호출
   - 200: 메인 화면으로 이동
   - 404: 프로필 입력 화면으로 이동

3. 프로필 입력 화면
   - 닉네임과 학년을 받아 POST /me로 전송

4. 마이페이지
   - GET /me로 표시, PATCH /me로 수정

이메일은 회원가입에서만 입력받음.
POST /me에 보내지 않아도 응답에 포함됨.


[5] API 호출 공통 코드
------------------------------------------------------------
/health를 뺀 모든 요청에 토큰이 필요함.

async function api(path, init = {}) {
  const { data } = await supabase.auth.getSession();
  return fetch(`${import.meta.env.VITE_API_URL}${path}`, {
    ...init,
    headers: {
      "Content-Type": "application/json",
      Authorization: `Bearer ${data.session?.access_token}`,
      ...init.headers,
    },
  });
}


[6] 요청 형식
------------------------------------------------------------
POST /me
{ "nickname": "우왕이", "grade": 2 }

PATCH /me (바꿀 항목만 전송)
{ "grade": 3 }

nickname
- 필수, 앞뒤 공백 제거 후 1~20자
- PATCH에서 null 불가

grade
- 선택, 1~3 또는 null
- PATCH에서 null을 보내면 삭제됨


[7] 응답 형식 (POST, GET, PATCH 공통)
------------------------------------------------------------
{
  "user_id": "uuid",
  "email": "student@example.com",
  "nickname": "우왕이",
  "grade": 2,
  "created_at": "2026-11-09T07:00:00+00:00",
  "updated_at": "2026-11-09T07:00:00+00:00",
  "n_reactions": 0,
  "traits": [
    { "code": "R", "label": "현실형", "group": "interest", "score": 0.0 }
  ]
}

- traits는 항상 11개 항목이 내려옴 (위 예시는 1개만 표시)
- score는 0~1
- group은 interest, style, value 중 하나
- 카드 반응이 쌓이기 전에는 score가 모두 0이므로
  "아직 분석 중" 같은 빈 상태를 준비할 것


[8] 에러 처리
------------------------------------------------------------
401  invalid_token       로그인 화면으로 이동
404  profile_not_found   프로필 입력 화면으로 이동
409  profile_exists      이미 등록됨. GET /me 후 메인으로 이동
422  항목별 오류 배열     입력값 오류 표시
503  auth_unavailable    잠시 후 재시도 안내

에러 내용은 응답 본문의 detail에 들어 있음.


[9] 카드 피드: GET /feed
------------------------------------------------------------
GET /feed?n=10   (n은 1~20, 생략하면 10)

응답
{
  "cards": [
    {
      "impression_id": "uuid",
      "source": "cold_start",
      "card_id": "c0001",
      "type": "job_day",
      "title": "수의사의 하루",
      "body": "아침엔 입원한 강아지 상태부터 확인해요. ...",
      "job_name": "수의사",
      "options": []
    },
    {
      "impression_id": "uuid",
      "source": "cold_start",
      "card_id": "c0002",
      "type": "a_vs_b",
      "title": "주말에 하나만 고른다면?",
      "body": "둘 중 더 끌리는 쪽은?",
      "job_name": null,
      "options": [
        { "id": "c0002-a", "label": "직접 가구 만들기" },
        { "id": "c0002-b", "label": "전시회 보러 가기" }
      ]
    }
  ]
}

type
- job_day: 직업 소개 카드. options가 비어 있음
- a_vs_b: 선택지 2개
- situation: 선택지 2~4개

source: personalized(맞춤), random(탐색), cold_start(초기 탐색)

- impression_id는 반응을 보낼 때 그대로 사용할 것
- cards가 빈 배열이면 더 보여 줄 카드가 없다는 뜻. "오늘 카드 끝" 같은 화면을 준비할 것
- 반응하지 않은 카드는 다음 GET /feed에 같은 impression_id로 다시 내려옴.
  새로고침해도 카드가 사라지지 않음
- 응답 순서대로 화면에 보여 줄 것


[10] 카드 반응: POST /reactions
------------------------------------------------------------
직업 카드(options가 빈 카드)
{ "impression_id": "uuid", "reaction": "like" }

선택형 카드(options가 있는 카드)
{ "impression_id": "uuid", "reaction": "choose", "option_id": "c0002-a" }

reaction
- like: 좋아요
- dislike: 싫어요
- save: 저장
- pass: 넘기기 (성향은 바뀌지 않고 반응 수에만 포함)
- choose: 선택지 고르기. 이때만 option_id를 보냄

응답
{ "status": "recorded" }

status가 duplicate이면 이미 반응한 노출이라는 뜻이고 성향은 다시 바뀌지 않음.
재시도 때 나올 수 있으므로 recorded와 똑같이 성공으로 처리할 것.

에러
404  impression_not_found   없는 노출이거나 내 노출이 아님. GET /feed 다시 호출
409  reaction_conflict      반응이 겹쳐 처리하지 못함. 같은 요청을 다시 전송
422  invalid_reaction       카드와 맞지 않는 반응 (예: 직업 카드에 choose, option_id 누락)
401, 503은 [8]과 동일

반응 후 GET /me를 호출하면 n_reactions와 traits에 반영된 값을 볼 수 있음.


[11] 현재 데이터 상태
------------------------------------------------------------
- 카드는 현재 122장 (직업 카드 120, 선택형 2). 선택형 카드는 추가 예정
- 모든 카드가 검수 전 초안이므로 문구가 바뀔 수 있음
- 카드 문구를 프론트에 하드코딩하지 말 것


[12] 연동 후 함께 확인할 것
------------------------------------------------------------
실제 로그인 토큰으로 아래 순서대로 호출해 볼 것.

1. POST /me
2. GET /feed
3. POST /reactions
4. GET /me (n_reactions가 1인지 확인)

백엔드에서 진짜 로그인 토큰과 실제 데이터 저장을 아직 검증하지 못했음.
오류가 나면 상태 코드와 detail을 백엔드에 전달할 것.
